# E2E テスト項目定義（Phase 1）

> 作成: 2026-09-20 ／ 根拠: `CLAUDE.md` §4.4 ／ `docs/spec/浮遊街アプリ 総合要件定義・設計書_v13.md`
> ／ `docs/spec/detailed-design/{API設計,画面設計,DB物理設計}.md` ／ `docs/spec/WBS_Phase1.md` `1-3`
>
> WBS `1-3`（テスト基盤）の残作業＝「**認可・金額計算・個人情報**の3領域の E2E シナリオ」の中身を、
> 正本と詳細設計から逆引きして確定したもの。本書が `1-3` の完了条件の実体である。

---

## 0. 方針

`CLAUDE.md` §4.4 が定める3つのルールをそのまま E2E に適用する。

1. **テスト名は「何をテストしているか」が読める文にする**（例: `ゲストはguest_allowed=falseのクエストを受注できない`）
2. **1テスト1アサーション**を目安に、失敗時に原因が一意に分かるようにする
3. **認可・金額計算・個人情報の取り扱いに関わるロジックは必ずテストを書く**

加えて、正本 v13 §5.9.3 の [!danger]「**DOM非表示は認可ではない**」に従い、
**認可のテストは「画面に出ない」だけでは合格としない。同じ資源への API 直叩きと PostgREST 直アクセスを必ず対で書く。**

### 0-1. 実行環境の前提（これが無いと本書は動かない）

| # | 前提 | 現状 | 担当 |
| --- | --- | --- | --- |
| P-1 | **E2E 専用 Supabase プロジェクト**（`E2E_SUPABASE_URL` / `E2E_SUPABASE_ANON_KEY` を GitHub Secrets のみへ登録） | **未作成** | WBS `1-1b`（オーナー作業） |
| P-2 | `ci.yml` の e2e ジョブから **`\|\| 'https://placeholder.supabase.co'` フォールバックを撤去**し、Secrets 未設定なら**落ちる**ようにする | フォールバックが残存 | 実装 |
| P-3 | `CLAUDE.md` §6.2「E2E は本番 Supabase を絶対に指さない」の遵守を CI で機械チェック | 未実装 | 実装 |
| P-4 | 各ロール（`admin` / `core_member` / `member` / `guest`）の**テストアカウントを storageState で事前生成**する fixture | 未実装 | 実装 |

> [!danger] いまの e2e ジョブの緑は「シナリオが空」だから成立している
> `ci.yml` の e2e ジョブは **skipped ではなく毎回実行され、毎回 success している**
> （`continue-on-error` も無く、落ちれば赤くなる）。緑になる理由は
> **唯一のテスト `smoke.spec.ts` が Supabase に一切アクセスしない**ため、
> `E2E_SUPABASE_URL` が偽値でも通ってしまうことにある。
>
> **本書の項目は1件目から Supabase を触る。**
> したがって P-1（E2E 専用プロジェクト）が無いまま項目を足すと、その瞬間に CI が赤くなる。
> **P-1 → P-2 の順で先に片付けること。**

### 0-1b. ★ 先に実装した「DBを要しない範囲」（2026-09-22）

上の P-1（E2E 専用 Supabase）はオーナー作業のため待ち状態だが、**未認証からの到達性だけは
ログインを伴わないため、いまの CI（プレースホルダの Supabase 値）でも検証できる**。
そこを先に実装した（`e2e/unauthenticated-access.spec.ts` ／ 17ケース）。

| 範囲 | 内容 |
| --- | --- |
| 保護経路の到達性 | `/quests`・`/orders`・`/me`・`/upload`・`/reservations`・`/shopping`・`/staff/*`・`/admin/*` の12経路が**未認証ではログイン画面へ送られる** |
| 未認証で開く経路 | `/login`・`/api/health`・`/reserve`（公開予約＝未ログインの入口） |
| 未認証の API | `POST /api/media/signed-upload-url` と `GET /api/quests` が **401** |

⚠️ **`/reserve` はステータスを見ない。** この画面は表示の材料を `service_role` で読むため、
キーを持たない CI では 500 になる（`src/app/reserve/page.tsx` の注記）。
固定したいのは「未ログインの入口であり、ログインへ飛ばさないこと」である。

⚠️ これで **P-1 が不要になったわけではない**。ロール別（A-1 以降のほとんど）・金額・個人情報の
項目は1件目から Supabase を触るため、引き続き P-1 → P-2 の順で片付ける必要がある。

### 0-2. 記法

- **ID**: `E2E-<領域><連番>`。領域 = A 認可 / B 金額計算 / C 個人情報 / D 通し
- **前提**: そのテストが書けるようになる WBS パッケージ
- ✅ = 前提パッケージが完了済み（今すぐ書ける） / ⬜ = 前提が未完
