### なぜ `role_filter` オフのまま入れたのか

本番テナントは `feature_flags.role_filter` が**オフ**で、`target_role` は絞り込みに使われません。
つまり現時点では、**LINEで質問すれば誰でもこの50件を読めます**。

これは**「プレリリースまではコンシェルジュを運営しか触らない」というオーナー判断**（2026-08-23）を
前提にした運用です。`target_role=member` を先に付けてあるので、**スイッチを入れた瞬間に自動で運営限定**になります。

> [!important] 権限を分けるのは「個人情報・原価を入れるとき」
> オーナー方針（2026-08-23）：**個人情報や原価をコンシェルジュに読ませる必要が出た時点で、権限を分ける。**
> それまでは分けない。したがって、§3 の禁止事項に触れるデータを入れたくなったら、
> **入れる前に `role_filter` の有効化と利用者ロール登録の整備を先に行う**こと。順番を逆にしない。

## 2. 登録内容の内訳（`ops-01` 〜 `ops-50`）

| ID | 領域 | 主な内容 |
| --- | --- | --- |
| `ops-01`〜`ops-03` | 権限・全般 | 運営2ロールの違い、「親方」は権限ではない、1日の起点は顧客管理画面 |
| `ops-04`〜`ops-05` | 朝会 | 録音〜議事録・クエスト候補の自動生成、候補は人が補正してから公開 |
| `ops-06`〜`ops-15` | 宿泊 | 予約経路2本、TimeTree不使用、自動確定の条件、6形態66名の収容枠、名称変更、部屋割当、キャンセルと宿泊券 |
| `ops-16`〜`ops-19` | 注文・提供 | チェックイン中限定、会計と提供の2軸、「精算済みなのに未提供」、SOLDOUT権限 |
| `ops-20`〜`ops-25` | クエスト | 二段階承認、最終承認は管理者のみ、確認は1人で成立、資格ゲート、Eumo給付と14日滞留 |
| `ops-26`〜`ops-34` | 会計 | Uii主・円副、単品ごとの換算、精算QR経由、伝票編集ルール、QR失効、遡及修正と差額繰越、顧客一覧の並び順 |
| `ops-35`〜`ops-40` | 会員管理 | 名寄せ、複数候補は承認キュー、連絡先なし105名、再訪アラート、宿泊券の手動増減、街人登録の承認 |
| `ops-41`〜`ops-43` | マスタ管理 | メニューは管理者のみ・Uii価格は自動、料金改定は期間を区切って追加、過去伝票は影響を受けない |
| `ops-44`〜`ops-47` | コンシェルジュ | API連携なし、未回答問い合わせの運用、登録禁止情報、ロール定義の正本 |
| `ops-48`〜`ops-50` | 事故防止・未決 | やってはいけないこと12点、「非表示≠不許可」、未決事項8点 |

全文は `line-rag-bot/scripts/import_operations_manual.py` の `SEEDS` を参照してください。
各件に `source_ref`（マニュアルの節番号と正本の項番）を持たせてあるので、回答が疑わしいときは一次情報まで辿れます。

## 3. 🚨 登録してはいけないもの（投入前の点検表）

**新しくナレッジを足すときは、必ずこの表で点検してから登録してください。**

| 種別 | 例 | 理由 |
| --- | --- | --- |
| 鍵・設備の扱い | どこに何があるか、開け方、保管場所 | LINEのロールは自己申告（member／guest の2値）で詐称できる。「運営です」と言うだけで到達する |
| 原価・仕入単価 | 仕入先、原価率 | 同上 |
| 会員個人の情報 | 氏名・連絡先・運営メモ・宿泊履歴 | LINE側に会員データを参照する経路は無いが、ナレッジとして書けば漏れる |
| 裏付けのない具体値 | チェックイン時刻、Wi-Fiパスワード、静音時間 | 過去に架空の出典を持つQ&Aサンプルが混入した事例がある（`line-rag-bot/docs/09` §2） |
| 古い仕様 | 「eumoアプリで送金する」等のUii直接決済を前提とした案内 | 現行仕様と矛盾する（v13 §5.5.1） |

## 4. マニュアルを直したときにやること

**マニュアル本文とコンシェルジュの回答は自動では同期しません。**

1. `docs/operations/現場運用マニュアル_運営スタッフ向け.md` を直す。
2. `line-rag-bot/scripts/import_operations_manual.py` の該当 `Seed` を直す。
3. `--apply --allow-production` で再実行する（`doc_id` 固定なので上書きになる）。
4. マニュアルの改訂履歴に反映日を書く。

これを飛ばすと、**LINEのコンシェルジュだけが古い手順を答え続けます。**
実装が進んで仕様が変わったときも同じです（現時点の50件は「設計上こう動く」であり、実機検証を経ていません）。
