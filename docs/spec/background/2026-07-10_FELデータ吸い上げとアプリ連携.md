# FELデータ吸い上げとアプリ連携

### 🧑 User

浮遊街アプリ、FELのデータの吸い上げ方

### 🤖 Gemini

資料に基づいた「浮遊街アプリ」および「FEL（Favorite Earth Life）」におけるデータの吸い上げ方（共有・収集方式）の詳細は以下の通りです。

##### 1\. FELのデータ吸い上げ方式（受講生・モデルケースからの収集）

FELのデータパートナー制度における現場データの吸い上げは、通信環境の制約を考慮して以下の方式が計画されています。

*   **手動エクスポート方式の採用**
    *   山林や別荘など、インターネットの電波が弱い立地での利用を想定しているため、常時接続によるWi-Fi自動送信は見送られています。
    *   代わりに、 **USBまたはBluetoothを用いた手動エクスポート方式** を採用し、 **3ヶ月に1回** の頻度でデータを吸い上げる設計となっています。
*   **2段構えの収集構造**
    *

### 🤖 基本層（広く浅く）

受講生の任意参加（想定応募率30%）により、振り返り支援を兼ねて基本的な観察・実行データを収集します。
    *

### 🤖 モデルケース層（選抜・深く）

一部の受講生（想定選定率10%）をモデルケースとし、個別相談や機材貸与を行うことで、より解像度の高いディープなデータを吸い上げます。

##### 2\. 浮遊街アプリとFEL間のデータ連携・共有方式

両システム間でのデータ共有やシステム的な吸い上げについては、完全に物理インフラを統合するのではなく、 **疎結合な連携** を前提としています。

*   **データモデル（語彙）の共通化（先行対応）**
    *   アプリケーションやデータベース自体は完全に分離されていますが、将来的なデータ相互活用のために「場所データモデル（静的な土地プロファイルと、時系列の作業・変化ログの2層構造）」の項目定義（型）をはじめから共通化して蓄積します。これにより、後からデータを移行・統合する際のコストを抑えます。
*   **MCP（Model Context Protocol）経由のデータ連携**
    *   システム間でのデータ共有は、APIを個別に構築するのではなく、 **MCP経由を第一選択** として設計されています。
    *   共通の「MCP Gateway」を介して、「Place Data MCP Server」などが場所データ、環境データ、作業ログなどを吸い上げ、AI（Claude基盤）がコンテキストとしてシームレスに参照・利用できる仕組みが検討されています。
