1.  プロジェクト概要 1.1 背景 自給自足コミュニティ「浮遊街」におけるクエスト運営、会員管理、地域通貨「Uii（ウイ）」運用およびFAQ対応について、現在は人手による運営負荷が高い。 本システムは、これらの運営業務をデジタル化し、AIを活用した運営支援を実現することを目的とする。また、日本円などの既存通貨を介さず「腐る経済」を軸とした特異なコミュニティの持続可能性を高める。 さらに、コミュニティ内に存在する暗黙知（キッチンの配置や作業ノウハウ等）を行動の文脈（Situated Action）に合わせて引き出せるよう形式知化（ケースベース推論）する。AIのベクトル検索を活用し、コミュニティの複雑な情報（高次元空間）からユーザーに最適な解（低次元の正解）を提示する量子力学的なファシリテーション・アプローチを取り入れ、将来的には複数コミュニティへの展開（マルチテナント化）およびFEL（Favorite Earth Life）とのデータ連携を見据えた基盤として構築する。 1.2 システム目的 業務効率化と負荷軽減 クエスト管理のデジタル化（手動運用の自動化・効率化） FAQ自動回答と暗黙知のデータベース化（ボラスタ・待ち人向けナレッジ共有によるコアメンバーの負担軽減） Uii運用・決済支援（EUMO連携による帳簿・残高管理） 利用者体験向上と摩擦ゼロのUI 情報へのアクセス性向上と、認知モデルに合わせたAIコミュニケーション クエスト参加促進・貢献の可視化とゲーム性の提供 将来展望とテクノロジー連携 AIによる自律支援（朝の会議録音からのクエスト自動作成、Claude×Obsidianの連携） IoTの活用（蜂の巣チェック等の重労働の省力化とFELデータ収集） 複数コミュニティ展開（マルチテナント基盤構築） FEL（Favorite Earth Life）との共通データ連携
2.  システム概要 システム名称: 浮遊街アプリ 利用者分類: 管理者: 運営スタッフ・コアメンバー（カフェ・宿泊に携わる人） 会員: 街人（一般コミュニティメンバー）、ボランティアスタッフ ゲスト / 長期滞在者: 初回来訪者または長期宿泊者（※ゲストおよび長期滞在者は基本同一権限とする） カスタム権限: 出資者・VIP等の特殊権限設定
3.  開発方針 MVPの早期構築: 最小限の機能で短期間構築し、現場で運用しながら高速に改善する。Figma等を用いたUI/UXの事前設計（アカウント画面等のレイアウト作成）を行う。 摩擦ゼロのアカウント設計: 厳密な個人情報（本名・クレジットカード等）は持たず、UUMO（eumo）側に処理を委譲する。 AIと暗黙知の活用（MDワールド連携）: AI（Claude API）とObsidian等を組み合わせ、現場のヒアリングから得た暗黙知を形式知化してRAGで運用する。 マルチテナント・疎結合設計: 浮遊街固有のロジックと共通基盤を分離したアーキテクチャを採用する。 EUMOとの連携: 地域通貨「Uii」の残高管理の正（SSOT）は外部基盤（EUMO）とし、アプリ側は非同期参照・キャッシュを行う。
4.  スコープ Phase 1（MVP：2026年7月〜8月） 認証・アカウント自動作成（外部予約連動の空枠作成、ニックネーム・誕生年月での摩擦ゼロ登録） クエスト管理（登録・編集・削除・閲覧・参加申請・完了報告） クエスト承認・査定（管理者/リーダーによる手動目視承認・Uii/XP付与） 注文管理・会計（客のスマホ注文 ＋ 店員タブレットのハイブリッド運用、POSデジタル化） Uii残高表示・失効管理（EUMO残高参照、3ヶ月有効期限一括失効） 宿泊管理機能（宿泊申込フォーム連携、滞在日数自動計算・自動減算、Googleカレンダー連動） 施設・フィールドマップおよび品目案内（P2Pマーケット前段としての案内表示） FAQ・暗黙知コンシェルジュ（RAG対応、プロファイル判別、キッチンの配置などボラスタナレッジ提供） 気候・環境データの収集基盤（IoTキットを用いた蜂の巣チェック等のデータ収集、FEL連携準備） Phase 2（2026年9月以降予定） スキルツリー機能（スキルレベルLv1〜5の可視化、熟練度連動の報酬動的算出、推薦機能） P2Pマーケット（スキル・物品の売ります/買いますマッチング） ベクトル検索による写真・データ共有（SNS運用自動化基盤） Phase 3（将来検討） AIによるクエスト自動生成（朝会録音・議事録解析による自動作成・承認フロー） FEL連携強化・IoT連携の拡張 マルチテナント化
5.  業務要件 5.1 認証・アカウント管理（摩擦ゼロUI） アカウント事前作成: 外部の宿泊予約フォームに予約が入った段階で、裏側でアプリのアカウント（空枠）を自動作成しておく。 ミニマルな登録情報: ユーザーには招待リンクを送り、初回アクセス時は「ニックネーム」と「誕生年月（概算）」のみを入力させる。 個人情報の非保持: 本名やクレジットカードなどの円情報はUUMO側で処理するため、アプリ内では原則として保持しない。（後々どうしても必要な場合のみ拡張を検討） ログイン手段: メール認証、Google OAuth、LINE OAuthを提供する。（MFAはPhase 1非対象） 5.2 クエスト管理 管理者: クエスト新規登録、編集、削除、募集人数設定、Uii報酬・難易度設定。 会員 / ゲスト: クエスト一覧閲覧、詳細確認、参加申請、完了報告。 反復実行: クエストは繰り返し実行可能とし、熟練度や担当スキルに応じて報酬を調整可能とする。 5.3 クエスト承認 管理者 / リーダー: 完了報告の内容を目視確認し、承認・差戻しを実施。承認完了時に自動でUii付与（EUMO連携）および獲得XP加算を行う。

#### 5.4 注文管理・会計売上分析（セルフ・代理ハイブリッド）客側のセルフ注文（スマホ）: ユーザーが自身のスマホからアカウントにログインし、メニューを選択して「カートに入れて注文」できるシンプルなUI。店員側の管理（タブレット）: 店員のタブレットには「誰（ニックネーム）が何を注文したか」がリアルタイムで一覧表示される。店員の代理入力（タブレット）: 品切れ時の調整や、客がスマホを持たずに口頭で注文しに来た場合、店員がタブレット上で「〇〇さんの代理で注文」として直接入力・決済処理を行える。5.5 宿泊管理機能宿泊申込・カレンダー連動: 事前の申込フォーム連携による予約データの自動登録。Googleカレンダーにニックネームで連携し「誰がいつ泊まるか、混雑状況」を可視化する。滞在期間管理: 現在の滞在日数自動計算、毎日0時に宿泊残日数を自動減算処理。宿泊延長は新規フォーム申請による再予約処理とする。5.6 クエストキャンセル機能会員キャンセル: 開始前まで任意でキャンセル可能。管理者キャンセル: 天候・運営都合による中止可能。ログを保管する。5.7 Uii機能・経済圏設計（腐る経済）SSOT: 残高管理の正はEUMO。アプリ側は非同期同期および一時キャッシュを保持。有効期限: 3ヶ月の有効期限を設定し、到達時は一括失効。マイナス残高の禁止: 残高不足の場合はエラーを返す。5.8 FAQ・暗黙知AIコンシェルジュ機能（RAG）暗黙知の形式知化: ボラスタインタビューで得た「キッチンの配置」「どこに何があり、どこに片付けるか」といった属人的なナレッジを形式知化し、認知モデルと状況（Situated Action）に合わせてAIが回答する。Claude × Obsidian連携: 情報と行動のケースを合わせた「暗黙知データベース（MDワールド）」を構築し、高次元のベクトル空間から最適な回答を抽出。コンテキスト切り替え: ログイン属性（メンバー/ゲスト/ボラスタ）を判別し、解像度を調整。信頼度低下時は未回答として管理画面へエスカレーション。5.9 気候・環境データおよび施設・IoT情報管理IoTの活用: 蜂の巣の大きさ・状態チェックなど、暑い中での重労働を軽減するため、Amazon等の安価なIoTキットを利用する。これを3Dプリンターで量産し、アプリと連携させて遠隔監視・データ収集を行う。環境・施設情報: カフェの平米数、床素材、アースバッグ構造等の項目定義と修繕履歴の蓄積。数字データはJSON、非構造化データはPDF/ベクトル化して保存。FEL連携を見据える。6. 権限マトリクス機能・操作項目管理者コアメンバー（店舗・宿泊）街人・ボラスタゲスト・長期滞在者ログイン / ログアウト〇〇〇〇クエスト閲覧・参加申請・完了報告〇〇〇〇（制限あり）クエスト定義・新規登録・編集・削除〇〇〇（自作のみ）

# 【浮遊街アプリ UI/UX 要件】

## 1. アプリの概要と世界観
- 自給自足コミュニティ「浮遊街」の専用Webアプリ（Next.js / Vercel想定のモック）。
- 地域通貨「Uii（ウイ）」、クエスト管理、宿泊残日数管理、および暗黙知AIコンシェルジュを包含する。

## 2. 実装してほしい画面構成（1つのHTML内でタブやボタンで切り替え可能にしてください）
