### 浮遊街クエストアプリ：総合要求仕様書

#### 1\. プロジェクト目的

自給自足コミュニティにおける生活・作業タスクを「クエスト」として管理し、スキル可視化・職業定義・貢献の承認を通じて、個人の成長とコミュニティの持続的な循環を支援する。

#### 2\. システム機能要件

##### 2.1 クエスト管理システム

*

### 🤖 タスク階層化

メインクエスト（季節の作業）、サブクエスト（日次作業）、期間限定クエスト（イベント）。
*

### 🤖 XP（経験値）システム

作業内容と労働時間に基づきXPを付与。
*

### 🤖 承認フロー

クエスト完了報告に対し、コミュニティリーダーまたは査定員による承認プロセスを実装。

##### 2.2 スキル・役割管理（職業システム）

*

### 🤖 スキルLv定義

Lv1（見習い）～Lv5（師匠）の5段階評価。
*

### 🤖 職業マトリクス

スキルLvの組み合わせによる「職業（ジョブ）」の自動付与。
    *   例：農業Lv3 ＋ 料理Lv2 ＝「里のシェフ」
*

### 🤖 推薦機能

メンバー同士で「この技術が優れている」と推薦し合うことで、スキルLv上限を解放する。

##### 2.3 コミュニティ運営機能

*

### 🤖 貢献度可視化

季節ごとの貢献ランキングと、チーム全体の目標達成率の表示。
*

### 🤖 遠隔貢献フロー

現地に行けないメンバー向けに「資料作成」「オンライン広報」「相談役」などの専用クエストを割り当て。

#### 3\. プロジェクトマネジメント（知識エリア）

本プロジェクトを遂行するにあたり、以下のエリアを重視する。 | 知識エリア | 重点項目 | | ------ | ------ | | **統合管理** | 各機能の進捗とリソース（人・時間）の一元管理 | | **スコープ管理** | MVP（最小機能版）を定義し、過剰な機能追加を抑制 | | **スケジュール** | 季節の農作業スケジュールに連動したマイルストーン設定 | | **コスト管理** | ノーコードツール（Glide/Bubble等）活用による開発費の圧縮 | | **品質管理** | コミュニティメンバーによるフィードバック回数と改善サイクルの確立 |

#### 4\. 開発ロードマップ（フェーズ別）

1.

### 🤖 Phase 1（MVP開発）

クエスト登録・完了承認・個人スキルLv表示機能の実装。
2.

### 🤖 Phase 2（コミュニティ実装）

メンバー間推薦機能、職業称号システムの導入。
3.

### 🤖 Phase 3（最適化）

遠隔貢献機能の強化、年間カレンダーと連動した自動通知の実装。

#### 5\. 技術選定の推奨

*

### 🤖 開発基盤

ノーコード/ローコード開発（Glide, Bubble, FlutterFlow等）を推奨。
*

### 🤖 データ管理

Google Sheets または Airtable（柔軟な修正と外部共有が容易なため）。
*

### 🤖 通知

LINE Messaging API または Slack API との連携によるタスクリマインド。
