# 職務経歴書：現場体験型要件定義

### 🧑 User

ここでの職務経歴書に記載する形でまとめて 機能要件を作るときはユーザーの業務を体験しながらを意識

### 🤖 Gemini

これまでの「浮遊街アプリ／浮遊街AI」および関連プロジェクト（FEL連携・RAGチャットボット導入等）における取り組みを、職務経歴書にそのまま掲載・調整して使える形式で整理いたしました。 「 **実際のユーザー業務・コミュニティ生活に自ら入り込んで体験し、現場目線で要件を抽出・定義した** 」という強みを前面に出した構成にしています。

* * *

##### 職務経歴書（抜粋案）

###### 職務要約

自給自足型コミュニティ「浮遊街」における運営効率化およびコミュニティ活性化を目指し、AIおよび独自経済圏（地域通貨）を組み込んだコミュニティ基盤アプリ（Web/LINE）の企画・要件定義・アーキテクチャ設計を推進。 **単なるデスクワーク上の要件定義にとどまらず、自ら現場に赴きユーザー（コミュニティメンバー／ゲスト）の農作業・施設管理・生活業務を直接体験・伴走することで、現場オペレーションに深く即した機能要件およびAIナレッジの策定を実現** 。また、将来的なマルチテナント化および別事業（FEL）とのデータ連携を見据えた拡張性高い概念データモデル・システム構成を策定。

* * *

###### ［主要プロジェクト履歴］

**【プロジェクト名】** 自給自足コミュニティ「浮遊街」AI統合アプリ設計・要件定義および将来連携構想 **【期間】** 2026年◯月 〜 現在 **【役割】** ITコンサルタント / 要件定義・システムアーキテクト / PMO **【担当領域】** 業務調査（現地伴走）・要件定義（機能・非機能）・AI/RAG設計・データモデル設計・アーキテクチャ検討

* * *

###### ■ プロジェクト概要

地域通貨「Uii」、労働のゲーム化（クエスト制）、回遊型コミュニティという独自のシステムを持つ「浮遊街」において、運営負担削減・メンバーのスキル可視化・AIサポートを目的とした統合アプリケーションを企画。また、長期的なランドスケープ教育事業「FEL（Favorite Earth Life）」とのデータ共有構想の策定を担当。

* * *

###### ■ 担当業務と取り組み（詳細）

**1\. 現場伴走型の業務ヒアリングおよび機能要件定義**

*

### 🤖 現地体験を通じた業務抽出

畑仕事、道具管理、宿泊管理、施設修繕、イベント設営など、 **実際の現場作業やコミュニティ生活を自身で体験・伴走** しながら業務プロセス（As-Is）を調査。現場の通信環境の制約や、作業者のスキル差による生産性の違い、属人化しやすい作業ノウハウ等の実態を把握。
*

### 🤖 機能要件・To-Beフロー策定

*

### 🤖 クエスト・貢献管理

現場体験に基づき、作業（農作業・広報・メンター等）をタスク化し、写真提出・査定承認・XP/地域通貨（Uii）付与を行う完了報告フローを設計。
    *

### 🤖 スキル・職業システム

スキルレベル（Lv1〜5）による工数算出ロジックおよび「推薦」「イベント企画」等の定性的なコミュニティ体験を要件としたRPG風の「転職クエスト」を要件化。 **2\. 生成AI / RAG（AIコンシェルジュ）基盤の企画・ナレッジ構築**
*   LINE Messaging API × Gemini/Claudeを活用したAIコンシェルジュ（チャットボット）の要件定義および管理機能（RAG管理画面）の仕様策定。
*   現地作業（草刈機等の機械操作、施設利用ルール）や決済手順（eumo連携）に関するナレッジを「現場の問いかけ」に合わせたQ&A構造として整理し、RAG検索用データベース（ベクトル化）へ登録・運用フローを確立。 **3\. データモデル設計および将来拡張アーキテクチャ（FEL連携）の策定**
*   会員、拠点・施設、クエスト、作業ログ、AI対話ログ等の主要エンティティを整理し、概念データモデルを定義。
*   将来的な「FEL」事業との連携を見据え、システム・インフラは独立（疎結合）させつつ、土地の静的プロファイルや作業ログといった「場所のDNAデータ」の共通語彙（Shared Schema）定義・MCP（Model Context Protocol）によるデータ連携設計を主導。

* * *

###### ■ 主な成果・工夫した点

*

### 🤖 現場目線による要件の解像度向上

「机上の空論」を排し、自ら現場作業者として行動したことで、ユーザーが直感的に操作できるUI/UX要件や、承認作業を阻害しないリアルな運用ルールを提示・合意形成。
*

### 🤖 拡張性を考慮した設計

開発スピードを担保しつつ、将来的な他コミュニティへのマルチテナント展開や外部基盤との連携コストを最少化する「データ定義先行型」の疎結合アーキテクチャを確立。

* * *

###### ■ 使用・検討技術スタック／ツール

*

### 🤖 AI / RAG

Claude API, Gemini, LLM Agent SDK, RAG（pgvector / line-rag-admin）
*

### 🤖 フロント／バックエンド／DB

Next.js, Supabase (PostgreSQL), MCP (Model Context Protocol), OpenAPI / TypeScript Schema
*

### 🤖 ツール・管理

Google Docs, GitHub, LINE Messaging API

* * *

##### アピールポイント（自己PR等で活用する場合の文面例）

**「現場第一主義の要件定義とドメイン理解力」** 新規システムやAIプロダクトの要件定義において、ドキュメント上のヒアリングに留まらず、ユーザーの実際の作業・現場オペレーションに深く没入して体験・伴走するスタイルを重視しています。「ユーザーが現場で何に躓き、どう感じているか」を身体感覚として捉えた上で機能要件やAIナレッジに落とし込むことで、現場に定着する手触り感のあるシステム設計・合意形成を実現します。
