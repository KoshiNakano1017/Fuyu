## v10 → v13 の主な変更点

1. **朝会録音・議事録自動生成 ＆ クエスト自動起案をPhase 1へ前倒し**（要件書 §5.1）
   録音 → Whisper文字起こし（話者分離）→ AI議事録（決定/共有/注意）→ クエスト候補の補正 → ワンタップでボード公開まで一気通貫。処理SLA「60秒以内」もUI上に明示。
2. **Uiiを「会計管理特化」へ変更**（§5.5・開発方針4）
   即時残高減算を廃止し、**円価格の2割引換算（Uii = 円 × 0.8）**で請求額を算定。注文は「未会計」として計上し一括精算。個人残高・3ヶ月失効・EUMO直接参照は **Phase 2バッジ表示** に降格。
3. **クエストのライフサイクルを厳格化**（§5.3）
   `申請中 → 指示済み（いつ・どこで・何を）→ 報告済み（Before/After写真必須＋実施時間）→ 承認完了／差戻し`。承認時に確定支払Uiiを入力し、**Eumo送付リンクを発行**。日次（1日おき）承認サイクルを明示。
4. **マイログ画面を新設**（§5.4）— ユーザー本人によるログ透明化。本人側からも一括精算QRを表示可能。
5. **代理注文の誤請求防止**（§5.4）— 対象を「現在チェックイン中のユーザー」のみに限定。伝票の注文者変更・金額補正・取消も実装。
6. **宿泊法（旅館業法）対応**（§5.2・§7）— 住所・前泊地・後泊地/行先を登録フォームと顧客詳細に追加、宿泊者名簿の出力導線を設置。
7. **注文可能条件を「チェックイン中のみ」に限定**（§5.4／2026-08-08 追加ルール）
   Phase 1では**カフェ・直売所ともに**、注文できるのは現在チェックイン中のユーザーのみ。未チェックイン時は商品に `🔒 要チェックイン` を表示し、カート投入・注文確定をブロック（代理注文も同条件）。
8. **直売所の郵送購入をPhase 2機能としてプレビュー**（Phase 2／2026-08-08 追加ルール）
   会員登録済みの「街人（会員）」が来訪せずに購入できる導線。配送先は会員マスタの住所を初期表示。送料・生鮮品の品質保証・発送オペは未決事項として明示。
9. **権限は4分類**（§6）— 管理者／コアメンバー／街人・ボラスタ／ゲスト・長期滞在者。スマホヘッダーの「滞在中 / 滞在外」バッジは**デモ用の切替スイッチ**を兼ねており、タップすると未チェックイン状態のロックUIとPhase 2郵送購入の導線を確認できます。
   - **★ モックと本番の切り分け（2026-08-14 決定）**：**モック／プロトタイプではこのデモ用切替スイッチを維持してよい**（検証の利便のため）。ただし**本番実装ではロール切替を管理者（`admin`）のみに限定**し、それ以外のロールでは要素ごと描画しない（正本 §5.9.2）。
10. **RAGナレッジをゆうきさんナレッジへ刷新**（§5.6）— まかないレシピ・左官・草刈り・しばかり/枝払い・農作業ルーティン。
11. IoT環境監視は **Phase 3プレビュー** のまま維持。

## 子ノート仕様との整合対応（2026-08-08 第2次）

[[朝会議事録自動生成システム仕様]]・[[クエストシステム仕様]]・[[業務カテゴリ体系とAIエージェント設計]]・[[RAGシステム仕様]] と突き合わせ、以下を修正。

1. **朝会パイプラインを簡略版へ**（最も大きな乖離）
   `Whisper＋話者分離` → **Gemini APIへ音声を直接入力し、議事録とクエスト候補JSONを1API呼び出しで同時生成**。文字起こしから話者ラベルを削除し、「話者分離は不要と判断」と明記。推奨マイク（**EMEET M220クラス／360度集音・1万円弱**）と前提（対面・通信安定）をUIに表示。
2. **業務ドメイン15分類に準拠**
   クエストのカテゴリを独自の文字列から `categoryId`（①施設・環境管理／②建物管理／③宿泊運営／④飲食・カフェ／⑤農業・食循環／⑧広報／⑪EC）へ変更。貢献バッジもドメイン単位に再定義。
3. **実行形態（execution_mode）を追加** — onsite／remote／hybrid をバッジ表示。遠隔可能なクエスト（広報記事・SNS投稿制作）を追加し、独立カテゴリ化せずフラグで扱う設計を反映。
4. **資格要件の安全ゲートを実装** — `required_certification` と `Member.certifications` を照合。チェーンソー特別教育・小型車両系建設機械が必要なクエストは、未保有者には申請ボタンを出さず「🚧 受注できません」と表示。
5. **クエストキャンセル機能** — 会員は開始前まで任意キャンセル（Uii/XP付与なし）、管理者は天候・災害・運営都合で中止し理由・日時をログ保管、受注者へ差戻し通知。
6. **RAGのエージェント別ルーティング表示** — 回答に `ホスピタリティ／ランド／ガバナンス` と構造化タイプ（レシピ型／判断型／規程型）を表示。道具マスタ（芝刈り機＝混合油25:1→リコイルスターター）、`failure_patterns`（よくあるミス）も回答に反映。
7. **Phase 1最優先4本柱をダッシュボードに明示** — 飲食管理／宿泊管理／会計管理／朝会議事録への導線カードを追加。

## 顧客管理画面の伝票編集を実装（2026-08-09 第3次 / 正本 v1.9.4）

要件書 §5.6・§5.5 の追加に合わせ、⑥顧客管理を「見る画面」から「直す画面」へ拡張。

1. **注文履歴のインライン編集** — 顧客詳細モーダルの注文履歴に ✏️ を追加し、伝票エディタを起動。商品明細の追加/削除/数量、**単価の上書き**、注文者の付け替え（既定はチェックイン中のみ／チェックボックスで全顧客へ切替）、**手動調整行**（値引き・追加請求をマイナス/プラスで追加）、決済ステータスの手動変更に対応。
2. **請求精算額の自動再計算** — 編集中に合計（円）・Uii・**変更前との差額**をリアルタイム表示。確定すると未会計合計・顧客一覧・マイログへ即時反映。
3. **Uii換算を「単品ごと」に変更**（★仕様変更）— `伝票合計 × 0.8` をやめ、**`floor(単価 × 0.8) × 数量` の合算**へ。商品カードのUiiを足した値と伝票・未会計合計が必ず一致するようになった。カート・代理注文・精算モーダルも同ロジックに統一。
4. **会計済み伝票も修正可能に**（★仕様変更）— 精算後の誤り救済のため遡及編集を許可。編集画面に警告を表示し、確定時に**差額（追加請求／返金）**を算出して顧客管理の請求パネルに残す。デモ用に会計済み伝票 `FY-1038`（たけし／コーヒー×2）を追加。
5. **誤操作防止** — 保存前に「変更前 → 変更後」の**差分プレビュー**、**編集理由の入力必須**、伝票ごとの**編集履歴ログ**（誰が・いつ・何を・なぜ）を表示。ユーザー側には `✏️ 運営により修正` バッジが出る。
6. **精算QRの自動失効** — 発行済みQRのある伝票を編集すると失効し、請求パネルに「再発行してください」の警告を表示。
7. **取消は論理削除** — 物理削除をやめ「取消」ステータス＋取消線で履歴に残す。
8. **未会計額のUii併記** — ヘッダー／マイログ／顧客一覧／顧客詳細／一括精算モーダルのすべてで ~~「円（主）＋ Uii（副）」~~ → **2026-08-20 に「Uii（主）＋ 円（副）」へ逆転**（正本 §5.5 ／ §9 #41）。**モック `prototype_v13.html` は旧表記のままであり、v14 で全画面の修正が必要**。

> [!warning] 正本 v13 側も同時に修正しました（Version 1.9.2）
> §5.1のステップ②③（Gemini直接入力・1API同時生成）、§9課題#1（話者分離不要・マイク機種確定）、§5.3（実行形態・資格ゲート）、§7（クエストのデータ項目追加）。子ノートの新しい決定が正本に未反映だった箇所の解消です。

## 動作確認済みのインタラクション

- 朝会：録音（タイマー）／サンプル15分音声の読込 → 4ステップ処理 → 議事録・全文文字起こし・候補4件生成 → 個別/一括公開でクエストボードへ反映
- クエスト：申請 → 指示出し → Before/After報告（両方必須）→ 承認（確定Uii既定値＝標準報酬）→ Eumoリンク発行・XP/バッジ付与
- 注文：カート → 未会計計上 → 顧客管理から一括精算QR → 会計済みへ更新
- **チェックイン判定：滞在外の街人はカフェ・直売所ともに購入不可、滞在中は購入可。ヘッダーの滞在バッジで切り替えて双方向に確認済み**
- 代理注文：チェックイン中のユーザーのみ選択可（滞在外の街人は選択肢に出ない）／SOLDOUTトグルが客画面へ即時反映
- FAQ：ナレッジ命中時は信頼度「高」＋出典表示、未命中時は「低」＋LINEエスカレーション → 代理返信 → 自動学習

## 未決事項（要件書 §9 と対応）

- 朝会録音時のマイク感度・騒音対策（無指向性マイク導入可否、Diarizationのチューニング）
- 連絡先を持たないゲストのアカウント同定方式 → モックでは「メール/電話による名寄せ」で仮実装
- 宿泊フォームとのデータ同期タイミング → モックでは「予約連動で空枠作成済み」前提のUI
- **直売所の郵送購入（Phase 2）の運用条件** → 送料・梱包の負担者、生鮮品の品質保証・クレーム対応、発送オペレーションの担当者、Uii決済とEUMO連携の扱い。モックでは無効化したプレビューUIとして表示

## 用語メモ

- **街人（まちびと）** ＝ コミュニティの会員。本モック・要件書では「街人・ボラスタ」として会員層を指す。
- 過去のAI会話ログ（v9系）に登場する「**待ち人**」は「街人」の表記ゆれ／誤変換と判明（2026-08-08 確認）。**2026-08-13 にクライアント確認済みで「街人」に確定**。「待ち人」は使用しない。
- **親方（おやかた）** ＝ コミュニティ内の立場を表す `member_type`。**システム権限は街人と同等**（`role='member'`）であり、認可には使用しない（2026-08-14 決定）。

   - 既定：①チェックイン中を最上部に固定 → ②未処理差額あり → ③未会計額の降順 → ④最終来訪日の降順。
