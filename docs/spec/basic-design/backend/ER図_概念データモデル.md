# ER図（概念データモデル）

> [[浮遊街アプリ 統合ナレッジベース (Master Index)]] の子ノート（セクション5）。本格的な物理ER図への橋渡しとなる概念エンティティ群を整理する。

## 主要エンティティ

### 1. 会員マスタ (Member)

> [!important] 物理スキーマは [[会員データモデル_ユーザーテーブル定義]] を正とする
> 2026-08-14 に実データ（街びと327件／親方衆44件）を受領し、**会員まわりを7テーブル構成へ正規化**した。本節は概念レベルの記述に留め、カラム定義・移行マッピングは同ノートを参照すること。

ID、属性（会員/ゲスト）、宿泊日数、スキルLv、職業ランク
- 詳細項目（v13準拠）：会員ID、氏名、ニックネーム、メールアドレス/電話番号、住所、前泊地、年齢、出身地、職業、会員種別、所持宿泊チケット数、通算宿泊数、獲得XP、保有バッジ
- **追加項目**：`certifications[]`（保有資格・講習修了：重機／チェーンソー／食品衛生責任者等）— 安全要件のあるクエスト受注時のバリデーションに使用（[[業務カテゴリ体系とAIエージェント設計]]参照）

**★ 2026-08-14 追加・変更点**

| 項目 | 内容 |
| --- | --- |
| `role` | `admin` / `core_member` / `member` / `guest` / `custom`。**認可はこれのみで判定する** |
| `member_type` | `親方` / `街人（コア）` / `街人（一般）` / `ゲスト`。**コミュニティ内の立場。認可には使用しない** |
| `account_status` | `pre_registered`（事前投入・未認証）／ `active` ／ `withdrawn` |
| `legacy_member_no` | 旧会員番号（街びとリストの `f` 列）。表示・照合用に保持 |
| **残高カラム** | `stay_tickets` / `total_stay_days` / `uii_balance` は**集計キャッシュ**。**正本は取引明細**であり、直接UPDATEを禁止しトリガーで再計算する |
| 分離した子エンティティ | `member_identifiers`（メール/電話/LINE/Discord。**欠損18.7%・重複ありのため単一カラム＋UNIQUEでは表現不能**）、`member_notes`（運営メモ・`core_only`） |

### 1-b. 会員権・プラン（新規／2026-08-14）

実データから、年会費・付与泊数・コインCB額が**会員種別で完全に決定される**構造が判明したため、マスタへ正規化する。

- **`MembershipPlan`**：プランコード、年会費額、付与泊数、付与Uii（CB）、権利期間（24ヶ月）
  - 第一弾＝40,000円/7泊/10,000 ／ 第二弾通常＝30,000円/4泊/5,000 ／ 第二弾ハイパー＝40,000円/6泊/10,000 ／ 新規登録（phase3）＝30,000円/4泊/5,000
- **`Membership`**：会員ID、プランID、開始日、満了日、ステータス、実際の入金額（個別調整の吸収用）
  - 満了日は第一弾が2027/4/30固定、第二弾は**開始日＋24ヶ月**で補完
  - **親方衆44名には `Membership` を作成しない**（宿泊券0泊。2026-08-14 決定）

### 1-c. 取引明細（新規／2026-08-14）

- **`StayTicketTransaction`**：会員ID、種別（初期付与／登録付与／消費／贈与／運営調整）、増減泊数、理由、操作者、日時 — **Phase 1 で稼働**
- **`UiiTransaction`**：会員ID、種別（CB付与／チャージ／利用／相殺／運営調整）、増減額、摘要、操作者、日時 — **Phase 2**（個人残高管理は Phase 2 のため、Phase 1 では移行しない）
- ※親方衆リストの金額は**円建ての預り金**であり Uii とは別勘定。**Phase 1 ではシステム化せずExcel運用を継続**する

### 2. 拠点・施設マスタ (Place)
静的プロファイル（緯度経度、気候帯、土壌タイプ、地形等）
- FEL連携を見据えた共通スキーマ項目（[[FEL連携アーキテクチャ]]参照）：方角、傾斜角度、周囲の植生、微細地形（谷・尾根・平地）
- 施設情報：名称、種別、受入キャパシティ、位置情報、建築プロファイル（構造、広さ、床素材等）

### 3. クエストマスタ (Quest)
業務定義、付与XP、Uii報酬設定
- 詳細項目：クエストID、タイトル、内容・定義、難易度、基本工数、募集人数、開催場所、時期、起案元区分（朝会自動抽出／手動起案）
- **追加項目**：`category_id`（業務カテゴリマスタ参照）、`execution_mode`（onsite／remote／hybrid）、`required_certification`（必要資格）
  - 「遠隔クエスト」は独立カテゴリではなく `execution_mode = remote` のフィルタ抽出として扱う（同一業務の二重登録を防ぐ）

### 4. 作業ログ (WorkLog / PlaceLog)
実行日時、担当者、Before/After写真、成果
- FEL共通スキーマとしての`PlaceLog`：気象条件＋場所（地形特徴）＋作業（クエスト）＋結果（収穫量、土壌改善度、状態変化）をセットで記録する因果ログ形式
- 浮遊街側の詳細項目：ログID、会員ID、クエストID、拠点・施設ID、日時、作業内容、使用資材、成果・評価
- **追加項目**：`issue_flag`（トラブル・失敗発生フラグ）、`issue_note`（内容）— 報告された失敗事例を後から `Recipe.failure_patterns` へ反映するフィードバックループの起点

### 5. 活動・対話ログ (Activity)
AIとの会話履歴、推薦・評価データ
- 監査・AIログ：操作者ID、操作日時、操作内容、AI対話ログ、信頼度スコア、エスカレーション履歴

### 6. レシピマスタ (Recipe)【クライアント要望 2026-08-08追加】
クエスト作業（草刈り・農作業・左官等）や調理（まかない等）の手順書。RAGの運営サポート機能から検索される（詳細は [[RAGシステム仕様]]）。
- 項目：レシピID、カテゴリ（調理／クエスト作業）、タイトル、材料・使用道具リスト（`Tool`と紐付け）、手順（ステップ配列）、所要時間、注意点・コツ、作成者ID、参照元URL
- **追加項目**：`failure_patterns[]`（よくあるミス：症状／原因／対処／発生条件）— 現場体験で得た失敗知見を構造的に蓄積する

### 7. 道具・資機材マスタ (Tool)【クライアント要望 2026-08-08追加】
クエストや調理で使う道具・機材を独立して構造化管理する。
- 項目：道具ID、名称、カテゴリ（農機具／調理器具／建築工具等）、使用手順（ステップ配列）、必要な消耗品（燃料・油等の混合比含む）、安全上の注意点、保管場所、点検・メンテナンス頻度、関連レシピID
- **追加項目**：`requires_certification`（要資格フラグ）、`safety_level`（安全リスク区分）— ユンボ・重機、チェーンソー等の安全ゲートに使用
- 例：芝刈り機＝「混合油をタンクに入れる」→「リコイルスターターを引いてエンジン始動」という手順を構造化データとして保持

### 8. 業務カテゴリマスタ (WorkCategory)【2026-08-08追加】
浮遊街で想定される全業務（15ドメイン）を階層構造でスキーマ管理する。クエストカテゴリ・スキルツリー・RAGカテゴリタグの共通基盤（詳細は [[業務カテゴリ体系とAIエージェント設計]]）。
- 項目：カテゴリID、ドメイン番号、名称、親カテゴリID、担当AIエージェント種別（ランド／ホスピタリティ／イベント／コミュニティ／クリエイティブ／ビジネス／ガバナンス／ストーリー）、RAG構造化タイプ（レシピ型／判断型／規程型）、標準実行形態、テナント固有フラグ
- 業務分類をハードコードせずマスタ化することで、マルチテナント展開時に浮遊街固有ドメイン（世界観・ストーリー系）のみ差し替え可能にする

## その他の主要データ（v13準拠）

### 朝会・議事録データ
朝会ID、実施日、音声ファイルURL、全文文字起こしテキスト、生成議事録サマリー、抽出クエスト案JSONリスト、作成者ID
- 録音ハード・パイプライン設計（マイク選定、Gemini音声直接入力による一括処理）の詳細は [[朝会議事録自動生成システム仕様]] を参照。

### チェックイン/アウトステータス
チェックインID、会員ID、チェックイン日時、チェックアウト日時、滞在フラグ

### 注文データ（会計管理）
伝票番号、購入者ID（チェックイン会員限定）、商品リスト、合計金額（円）、換算Uii額、決済ステータス、注文区分（セルフ/代理）、修正履歴ログ

### Uii取引情報
取引ID、送金者ID、受取者ID、金額、有効期限、付与/利用/失効履歴、EUMO同期メタデータ（詳細は [[Uii経済圏とeumo連携]]）

### ナレッジ・暗黙知マスタ
ナレッジID、カテゴリ（まかない/左官/草刈り/農作業等）、質問文、回答本文、作成者ID（詳細は [[RAGシステム仕様]]）
- **追加項目**：`agent_type`（担当AIエージェント種別）、`category_id`（業務カテゴリマスタ参照）— エージェント別にナレッジ空間を絞り込んでベクトル検索するためのルーティングキー
- **★ 2026-08-14 追加**：`target_role`（`guest`/`member`/`core_member`。**公開範囲＝検索フィルタキー。必須**）、`usage_scene[]`（利用シーン）、`keywords[]`、`knowledge_format`（`faq`/`manual`）、`attachments[]`（メディアID配列）、`review_status`（`draft`/`published`/`needs_review`）、`source_type`（手動／未回答ログ起点／朝会議事録抽出／スマホ現場登録）
  - `target_role` は**AI回答時のアクセス制御キーを兼ねる**。検索段階のメタデータフィルタで担保し、プロンプト指示による抑制に頼らない

### メディアアセット（新規／2026-08-14）

メディアID、ストレージパス（Cloud Storage for Firebase）、ファイル種別、`contentType`、サイズ、サムネイルパス、アップロード者、撮影日時・位置情報（Exif由来）、**用途タグ（`media_purpose`）**、紐付けキー（クエスト／ナレッジ／拠点／カテゴリ）、`usage_scene[]`、自動生成タグ（Vision API）、公開範囲（本体の `target_role` を継承）
- 認可判定は Supabase 側に一元化し、Firebase Security Rules には認可ロジックを置かない（[[システムアーキテクチャ]]）

### 街人登録申込（新規／2026-08-14）

申込ID、対象会員ID、申込日時、請求金額（30,000円）、付与宿泊券枚数（4枚）、申込ステータス（`申込中`/`QR送付済み`/`承認済み`/`却下`/`保留`）、決済QRトークン、QR発行者・日時・送付経路、有効期限・失効フラグ、入金確認者、承認日時、ロール昇格日時
- 決済はアプリ外（QR経由）で完結するため、**決済トランザクションそのものは保持しない**

### 差額精算（新規／2026-08-14）

調整ID、対象伝票番号、差額（円／Uii）、区分（追加請求／返金）、発生理由、ステータス（`未処理`/`精算済み`/`免除`）、発生日時、精算日時、操作者
- 差額は**次回チェックイン時に現地精算**する方針（[[浮遊街アプリ 総合要件定義・設計書_v13]] §5.6.6）

## エンティティ間の主な関連
- `Member` 1―N `WorkLog`（会員が複数の作業ログを持つ）
- `Quest` 1―N `WorkLog`（1つのクエストに対し複数人の作業実績）
- `Place` 1―N `WorkLog` / `PlaceLog`（拠点ごとの作業・環境変化の時系列）
- `Member` 1―N `Activity`（AIとの対話履歴）
- `Quest` 1―1 `Uii取引`（承認完了時にUii支払いが確定）
- `Recipe` N―M `Tool`（1つのレシピが複数の道具を使用し、1つの道具が複数のレシピで使われる）
- `Quest` 0―1 `Recipe`（クエストの標準作業手順としてレシピを参照する場合がある）
- `WorkCategory` 1―N `Quest` / `Recipe` / ナレッジマスタ（業務カテゴリが各データの分類軸となる）
- `WorkCategory` 自己参照（親カテゴリ―子カテゴリの階層構造）
- `Tool` N―M `Member.certifications`（要資格の道具は保有資格を満たす会員のみ使用可）

## 設計方針
- FEL側との共通語彙（`Place` / `PlaceLog` / `Member`）は独立したShared Schemaとして管理し、浮遊街固有の拡張項目（スキルLv、職業ランク、Uii関連等）は浮遊街ドメイン側のテーブル/フィールドとして分離する（[[システムアーキテクチャ]]のクリーンアーキテクチャ制約を参照）。
- 業務分類（`WorkCategory`）はコードにハードコードせずマスタテーブルで制御し、マルチテナント展開時にテナント固有ドメイン（世界観・ストーリー系）のみ差し替え可能にする。
