# 業務カテゴリ体系とAIエージェント設計

> [[浮遊街アプリ 統合ナレッジベース (Master Index)]] の子ノート。
> [[クエストシステム仕様]]（クエストのライフサイクル）と [[RAGシステム仕様]]（ナレッジ構造）をつなぐ**業務ドメインの全体地図**。

## 位置づけ

浮遊街は「クエスト＝業務のゲーム化」構造をとるため、**業務定義がそのままクエストマスタ／スキルツリー／RAGナレッジのカテゴリ体系になる**。本ノートはその最上位分類を定義する。

- 現場体験（調理・宿泊等）で得た知見をどこに格納するかの**受け皿**
- 将来的なマルチエージェント化（浮遊街AI＝街を運営するAI群）の**分割単位**

---

## 1. 分類の3軸モデル

業務を単一のリストで持つと破綻するため、**独立した3軸**で管理する。

| 軸 | 内容 | 用途 |
| --- | --- | --- |
| **軸1：業務ドメイン** | ①〜⑮の分類（下記） | クエストカテゴリ、スキルツリー、RAGのカテゴリタグ |
| **軸2：実行形態** | 現地必須 / 遠隔可能 / ハイブリッド | クエスト検索フィルタ（通い型メンバー向け） |
| **軸3：担当AIエージェント** | 8種のエージェント（下記） | RAGのルーティング、将来のマルチエージェントOS |

> [!important] 設計上の重要な補正
> 当初案の「⑮ 遠隔クエスト」は**業務ドメインではなく実行形態の属性**である。
> 「デザイン制作」「イベント企画」「営業」は現地でも遠隔でも成立するため、カテゴリとして独立させると**同じ業務が2箇所に重複登録される**。
> → `Quest` テーブルに `execution_mode`（onsite / remote / hybrid）フラグを持たせ、遠隔クエストは**フィルタで抽出**する設計とする。

また、実行主体で以下の2層に分かれる（従来整理の踏襲）。

- **クエスト層**：メンバー／ゲストが受注し、XP・Uiiを獲得する業務
- **運営オペレーション層**：管理者・コアメンバーが担う店舗／管理業務（[[機能要件定義]]の権限マトリクス参照）

## 2. 業務ドメイン一覧（軸1）

### 概観マトリクス

**RAG構造化タイプの定義**（[[RAGシステム仕様]]と対応）
- **レシピ型**：手順が定型化できる → `Recipe` × `Tool` マスタで構造化
- **判断型**：状況依存でケースバイケース → ケースベース推論（`{状況}+{アクション}={結果}`）で事例蓄積
- **規程型**：ルール・法令・基準 → 規程ドキュメント＋Q&Aペア

---

### ① 施設・環境管理
屋外・ランドスケープ全般。**重機とアート制作が同居する浮遊街らしいドメイン**。

- 草刈り（芝刈り機・草刈機操作）、施設造園、景観デザイン
- **ユンボ・重機オペレーション**、道路補修、排水整備
- 石積み、階段づくり、デッキ施工、フェンス施工
- **デコレーション・アート制作**、サイン・看板制作、ライトアップ設営、季節装飾
- 森林整備・間伐、薪割り・薪管理
- ビオトープ管理、雨水設備管理、サウナ管理、プール管理

> [!warning] 安全管理との連動が必須
> ユンボ・重機、チェーンソー（間伐）は**資格要件・安全確認が伴う業務**。
> `Quest` のスキルLv要件だけでなく、`Member` 側に**資格・講習修了フラグ**を持たせ、未保有者は受注できないバリデーションが必要（⑭ 法務・リスク管理と連動）。

### ② 建物管理・メンテナンス
①から分離することで、AIの回答精度と担当割当が明確になる。

- 建物点検、清掃、補修、左官、塗装
- 電気設備、水道設備、ガス設備、エアコン管理
- ガラス交換、屋根修繕
- 害虫対策、防災点検

### ③ 宿泊運営
[[機能要件定義]]のPhase 1最優先（宿泊管理）に直結。**チェックイン/アウトの前後に隠れた実作業が多い**。

- ベッドメイク、清掃、リネン交換、洗濯
- アメニティ補充、備品管理、忘れ物管理
- チェックアウト確認、客室点検
- レビュー返信

### ④ 飲食・カフェ運営
Phase 1最優先（飲食管理）に直結。**現場体験済みドメイン**。

- レシピ開発、メニュー改善
- 発注、原価管理、在庫・食材ロス管理
- ドリンク作成、パン・菓子製造
- 衛生管理、HACCPチェック、アレルギー対応

### ⑤ 農業・食循環
FEL連携（[[FEL連携アーキテクチャ]]）で `PlaceLog` の因果ログ対象となる中核ドメイン。

- 畑仕事、収穫、種まき、水やり
- 種採り、苗づくり、コンポスト・堆肥管理
- 養鶏、果樹管理
- 保存食づくり、発酵食品づくり、加工品製造、出荷

### ⑥ イベント運営
- イベント企画、タイムテーブル作成、登壇者対応
- 設営・撤収
- 配信、音響、照明、撮影、動画編集
- アンケート集計、アフターフォロー
- **社員研修の受入運営**（⑩ 営業・法人対応と連動）

### ⑦ 教育・コミュニティ運営
浮遊街の思想（[[プロジェクトの背景と目的]]：暗黙知の形式知化・技術継承）の中核。

- オリエンテーション、新人サポート、コミュニティ案内
- ファシリテーション、朝会運営、ワークショップ運営
- メンター、1on1
- クエスト設計、クエスト査定、人材マッチング

### ⑧ 広報・マーケティング
- SNS運営、記事執筆、ブログ、ニュースレター
- LP制作、バナー制作、チラシ制作
- 写真撮影、動画撮影、ショート動画制作
- プレスリリース、メディア対応
- **コミュニティ営業（知ってもらう活動・情報拡散）**、協賛営業、アライアンス開拓

### ⑨ デザイン制作
- ロゴ、イラスト、DTP
- 空間デザイン、展示物、看板
- UIデザイン、Webデザイン

### ⑩ 営業・法人対応
今後の収益源として拡大が見込まれる領域。

- 視察対応、**法人研修・パーティー等の誘致営業**
- 問い合わせ対応、見積作成、提案書作成
- 契約管理、リピートフォロー

### ⑪ EC・マーケット
浮遊商店街／メタバース連携（[[2026-07-23_メタバース連携とショップ・クエスト構想]]）の受け皿。

- 商品企画、商品登録、在庫管理
- 梱包、発送
- お客様対応

### ⑫ 財務・経営
- 会計入力、月次締め、予算管理、KPI集計
- 補助金申請、助成金申請
- クラファン運営、出資者対応

### ⑬ 人事・組織
- シフト作成、採用、オンボーディング
- 評価、面談
- クエスト設計、報酬（Uii/XP）計算

### ⑭ 法務・リスク管理
- 契約書管理、保険管理
- **宿泊法対応、食品衛生対応**（③④の前提条件）
- 個人情報管理
- 安全管理、災害対応

### ⑮ 世界観・ストーリー（浮遊街固有）
**他コミュニティには存在しない独自ドメイン**。マルチテナント化の際は「テナント固有ドメイン」として分離する対象。

- 世界観づくり、街の文化づくり
- RPGシナリオ制作、クエスト制作、ミッションデザイン、クエストバランス調整
- キャラクター制作、称号設計
- 街の歴史アーカイブ、街新聞制作
- Welcome体験設計、来訪者ガイド

## 3. 運営オペレーション層（管理者・コアメンバー）

| 店舗運営 | 注文対応、SOLDOUTトグル、代理注文 | 店員用タブレット画面 |
| 会計・レジ | 未会計アラート対応、一括精算QR、Uii/円換算 | 管理者PC画面 |
| 受付 | チェックイン/アウト、滞在日数・名寄せ | 宿泊管理機能 |
| 朝会運営 | 録音操作、議事録確認、クエスト自動起案の補正 | 朝会・議事録機能 |

## 4. AIエージェント分類（軸3）

業務カテゴリごとにAIを作るのではなく、**担当エージェント単位**で分割することで拡張性を確保する。将来的に「浮遊街AI」を**街全体を運営する専門エージェント群が協調するマルチエージェントOS**として設計できる。

| エージェント | 担当ドメイン | 主な知識ソース | RAG構造化タイプ |
| --- | --- | --- | --- |
| **ランドエージェント** | ① 施設・環境 / ② 建物 / ⑤ 農業 | `Recipe` × `Tool` マスタ、`PlaceLog` | レシピ型 |
| **ホスピタリティエージェント** | ③ 宿泊 / ④ 飲食 / 受付 | 調理レシピ、清掃手順、衛生規程 | レシピ型＋規程型 |
| **イベントエージェント** | ⑥ イベント運営 | 過去イベント事例、進行台本 | 判断型 |
| **コミュニティエージェント** | ⑦ 教育 / ⑬ 人事 / 朝会 | 議事録、1on1ログ、メンター知見 | 判断型 |
| **クリエイティブエージェント** | ⑧ 広報 / ⑨ デザイン | ブランドガイド、過去制作物 | 判断型 |
| **ビジネスエージェント** | ⑩ 営業 / ⑪ EC / ⑫ 財務 | 提案書テンプレ、価格表、助成金情報 | 規程型＋判断型 |
| **ガバナンスエージェント** | ⑭ 法務・安全 / 査定 | 法令、保険、安全基準、査定基準 | 規程型 |
| **ストーリーエージェント** | ⑮ 世界観・ストーリー | 街の設定資料、歴史アーカイブ | 判断型 |

### エージェント設計の含意

1. **RAGのルーティング**：ユーザーの質問をまずエージェント判定し、該当エージェントのナレッジ空間に絞ってベクトル検索する（検索精度向上＋トークン削減）。
2. **クリーンアーキテクチャとの整合**：Master Indexの制約通り、汎用エージェント（ランド／ホスピタリティ等）は `src/domains/core/` に、**ストーリーエージェントは浮遊街固有**として `src/domains/floating_city/` に隔離する。
3. **ガバナンスエージェントの横断性**：唯一、全ドメインに対する**制約チェッカー**として横断的に働く（例：重機クエスト受注時の資格確認、食品提供時の衛生要件）。
4. **段階導入**：Phase 1では「ホスピタリティ＋ランド」の2エージェント相当（＝現場サポートFAQ）のみ実装し、他は将来拡張とする。

## 5. データモデルへの含意

現行の [[ER図_概念データモデル]] に対して、以下の追加・変更が必要。

### 追加すべきエンティティ／項目

| 対象 | 追加項目 | 理由 |
| --- | --- | --- |
| **業務カテゴリマスタ（新規）** | カテゴリID、ドメイン番号、名称、親カテゴリID、担当エージェント種別、RAG構造化タイプ | 15ドメイン×多数業務をハードコードせずスキーマ管理する |
| `Quest` | `execution_mode`（onsite/remote/hybrid）、`category_id`、`required_certification` | 遠隔クエストのフィルタ抽出、資格要件バリデーション |
| `Member` | `certifications[]`（重機・チェーンソー・食品衛生責任者等） | ⑭ 安全管理との連動 |
| `Recipe` | `failure_patterns[]`（症状／原因／対処） | よくあるミスの構造的蓄積（前回提案の拡張） |
| `Tool` | `requires_certification`、`safety_level` | 重機・刈払機の安全ゲート |
| ナレッジマスタ | `agent_type`、`category_id` | RAGのエージェント別ルーティング |

### 重要な設計判断
- 業務カテゴリは**テーブル化してスキーマ管理**する（Master Indexのプロンプトルール「ロジックのハードコーディングを避け、JSON/スキーマで制御」に準拠）。
- ⑮ 世界観・ストーリーは**テナント固有ドメイン**として、マルチテナント展開時に切り離せる構造にする。

## 6. RAGナレッジ登録の優先順位

現場体験で得た知見を投入する順序。**Phase 1最優先の④→③から着手し、既存のレシピ×道具フレームワークを検証する。**

1. **④ 飲食・カフェ**（体験済み）— まかない調理レシピ、衛生管理、よくあるミス
2. **③ 宿泊運営** — ベッドメイク・清掃・リネン手順
3. **① 施設・環境** — 草刈機／芝刈り機、重機の安全手順（`Tool` マスタの本命）
4. **⑦ 教育・コミュニティ** — オリエンテーション、朝会運営（判断型の検証）
5. **⑭ 法務・リスク** — 宿泊法・食品衛生の規程Q&A（③④の前提）

各業務のナレッジ化は「現場ナレッジカード」テンプレート（状況／手順／よくあるミス／コツ／Q&A化）に沿って構造化する。詳細は [[RAGシステム仕様]] を参照。
