> [!note] 本分析の前提
> 浮遊街は**商用ホテルではなく、1,000人限定の会員制・自給自足コミュニティ**です。したがって業界標準機能の一部（OTA連携・レベニュー管理・宴会/婚礼など）は**業態的に不要**である可能性が高く、Gap＝欠陥とは限りません。ステップ4で「意図的な対象外」と「見落としの可能性あり」を仕分けています。

## ステップ4：Gap の仕分け

### 🔴 見落としの可能性あり（法令・実務リスク）

| #        | 標準機能                | 理由                                                                           |
| -------- | ------------------- | ---------------------------------------------------------------------------- |
| **B-08** | **消費税計算**           | **全16ファイルで「税」の記載が0件。** メニューは「2,100円」の総額表記のみで、内税/外税の別も不明。売上計上・領収書発行のいずれにも影響する |
| **B-09** | **軽減税率（8%／10%）**    | **カフェ（店内＝10%）と直売所（持帰り＝8%）が併存**する業態。区分できないと税額が誤る                              |
| **B-10** | **インボイス（適格請求書）**    | 会員・事業者が経費計上する場合に必要。登録番号・税率別合計・区分記載が未定義                                       |
| **B-16** | **アレルゲン表示**         | [[カフェメニュー]] で「Phase 2 以降検討」と**明示的に後回し**。飲食提供を開始する時点で判断が要る                 |
| **A-11** | **宿泊キャンセル・ノーショー**   | 宿泊券が消費されるのか返却されるのかが未定義。現場で必ず発生する ✅ **正本 §9 #27 に起票済み（2026-08-15）**             |
| **C-09** | **会計帳票（日次売上・税区分別）** | B-08〜B-10 と連動。経理・確定申告の基礎資料が出せない                                              |
| **C-11** | **法定保存年限の区分**       | 「監査ログ10年」のみ。宿泊者名簿・帳簿・衛生記録で年限が異なる                                             |

### 🟡 要確認（業態次第で要否が変わる）

| #               | 標準機能          | 判断ポイント                                                                             |
| --------------- | ------------- | ---------------------------------------------------------------------------------- |
| **A-06 / A-07** | **部屋割当・部屋台帳** | **「部屋」エンティティが存在しない**。ドミトリー等で部屋管理が不要なのか、単に未定義なのかで扱いが変わる。宿泊者名簿は出せるが「誰がどこに泊まったか」は残らない ✅ **正本 §9 #28 に起票済み（2026-08-15）** |
| **A-02**        | 空室在庫管理        | 予約が外部フォームのままなら不要。アプリで予約を受けるならオーバーブッキング防止が必要                                        |
| **A-01**        | 予約のCRUD       | 外部フォームを正とし続けるのか、アプリへ寄せるのかの方針判断                                                     |
| **B-13 / B-14** | 在庫・原価管理       | [[業務カテゴリ体系とAIエージェント設計]] に業務としては存在。システム化するかは Phase 判断                               |
| **B-17**        | HACCP記録       | 提供規模により義務範囲が変わる                                                                    |
| **C-06**        | PCI DSS       | カード情報を保持しない設計なら対象外。**「対象外」と明記する**のが安全                                              |
| **C-14**        | 勤怠・シフト        | ボラスタ運用のため、クエストで代替できる可能性                                                            |
| **B-19**        | 調理進捗管理        | 小規模なら口頭で足りる                                                                        |

### 🟢 意図的な対象外と判断してよいもの

| # | 標準機能 | 理由 |
|---|---|---|
| A-03 | 料金・レートプラン | **宿泊券（泊数）モデル**を採用しており、日別料金の概念が無い |
| A-04 / D-02 | OTA連携・予約流通 | 1,000人限定の**会員制**。一般流通に乗せない |
| A-12 | レベニュー指標 | 収益最大化を目的としない業態 |
| B-07 | 分割会計 | 個人単位の未会計計上で代替 |

## 総括

**独自機能（クエスト・朝会AI・RAG・Uii）は業界標準を大きく超える一方、飲食業の基礎である「税」が完全に空白**という偏りがあります。カバレッジ34%という数字自体は、会員制コミュニティという業態を踏まえれば低すぎるとは言えません（Gap 23件のうち9件は意図的な対象外と判断できます）。

ただし**優先度1〜3（税・キャンセル・アレルゲン）は業態に関わらず必要**です。特に税は、メニュー価格が総額表示されているだけで内税/外税の区別すらないため、**現状のままでは正しい領収書が発行できません**。

優先度4（部屋の要否）は、**会員データ移行を実施する前に決める**ことを推奨します。後から「部屋」を足すと、チェックイン・宿泊履歴・名簿出力に横断的な影響が出るためです。
