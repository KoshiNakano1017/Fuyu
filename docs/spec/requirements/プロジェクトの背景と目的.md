# プロジェクトの背景と目的

> [[浮遊街アプリ 統合ナレッジベース (Master Index)]] の子ノート（セクション1）

## 対象コミュニティ
- **浮遊街**：1,000人限定の通い型自給自足コミュニティ。
- 従来は人手による運営負荷（クエスト運営、会員管理、顧客管理、地域通貨「Uii」運用、FAQ対応）が高く、これをデジタル化・AI支援によって解消することが目的。

## コアコンセプト

### 1. クエスト制
コミュニティ内の作業（農作業、広報、メンター、左官、草刈り等）をクエスト化し、ゲーム感覚で貢献を可視化する。単なるタスク管理ではなく、スキルレベルや職業（ジョブ）と連動した成長システムとして設計する。

### 2. Uii（ウイ）— 腐る経済
- 日本円などの既存通貨を介さない独自の地域通貨。
- 「腐る経済（減価する通貨）」の思想を体現し、価値の滞留ではなく循環を促す（有効期限付き・失効の仕組み）。
- 実際の資金決済は外部基盤 **eumo** に委ね、浮遊街アプリ側は帳簿・メタデータ管理に徹する（詳細は [[Uii経済圏とeumo連携]]）。

### 3. 暗黙知の形式知化
- コミュニティ内の属人化した知識（ゆうきさんのまかないレシピ、左官、草刈り、農作業ルーティン等）を、現場の文脈（Situated Action）に応じてAIが引き出せる形式知として蓄積する。
- 認知モデルとしては「ケースベース推論（状況とアクションのペアを蓄積し、類似状況で再利用する）」を採用（詳細は [[RAGシステム仕様]]）。
- 背景思想として「量子力学的な高次元空間からの重み付けによる次元圧縮」とベクトル検索の類似性が議論されている（暗黙知→ベクトル空間への埋め込みという比喩）。

## システム目的（サマリ）
- **業務効率化とワンオペ負荷の極小化**：クエスト管理・注文管理・顧客管理の一元化、朝会音声からの議事録自動生成とクエスト自動起案。
- **利用者体験向上と摩擦ゼロのUI**：招待リンクからニックネームのみで参加できる低摩擦なオンボーディング、自身の履歴を確認できる透明性。
- **将来展望**：
  - 複数コミュニティへのマルチテナント展開
  - FEL（Favorite Earth Life）との共通データ連携・IoT遠隔監視
  - メタバース連携（職業に応じたマイショップ機能等）

## 開発方針の要点
1. MVPの早期構築・現場摩擦ゼロを優先し、短期間で構築して現場運用しながら高速改善する。
2. AI（Claude API等）は人間の運営業務を補助・支援する位置づけとする。
3. マルチテナント・疎結合設計（Shared Schema等）を前提としたアーキテクチャを採用する。
4. Uiiの残高管理はSSOT（信頼できる唯一の情報源）をeumo側に置き、アプリ側は非同期参照・キャッシュを行う。
