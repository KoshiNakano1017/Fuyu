# 朝会議事録自動生成システム仕様

> [[浮遊街アプリ 統合ナレッジベース (Master Index)]] の子ノート。[[クエストシステム仕様]] の朝会関連機能を詳細化したもの。クライアント最優先4本柱の1つ（[[機能要件定義]]参照）。

## 前提条件（クライアントヒアリング 2026-08-08）
- 朝会は**対面（オンラインではない）**で実施。
- マイクなどのハードウェア投資は**未定**（候補提示が必要）。
- 朝会実施場所の通信環境は**安定**しており、録音終了後の即時アップロードが可能。
- 参加人数・発言スタイルは「決定事項とタスクさえわかればよい」ため、**話者分離（誰が発言したか）は不要**。

これらの前提により、当初検討していた「話者分離付きSTT」「オフラインファースト設計」は不要と判断し、パイプラインを簡略化した（下記）。

## 音声入力（ハードウェア）候補
| 価格帯 | 機種例 | 特徴 |
| --- | --- | --- |
| 〜3千円 | サンワサプライ MM-MCU02、BOYA BY-M1（ラベリアマイク） | 内蔵マイクより改善するが屋外の風切り音に弱い |
| **7千〜1.5万円（推奨）** | **EMEET M220** / Anker PowerConf S3 | 360度集音＋AIノイズキャンセリング搭載。USB-C/Bluetoothでタブレット/PCに接続するだけ。話者分離が不要な本要件には十分なスペック |
| 3万円〜 | Zoom H1n等のフィールドレコーダー | 高音質だが録音→手動アップロードの一手間が増え、ワンオペ方針に反するため非推奨 |

→ まずは**EMEET M220クラス（1万円弱）**を購入し、精度が不足する場合のみ上位機種を検討する運用を推奨。

## パイプライン（簡略版）
話者分離が不要かつ通信環境が安定しているため、Google STT等を介さず**Gemini APIの音声直接入力（マルチモーダル）**に一本化し、文字起こしと要約を1ステップで完結させる。

```
① 録音
  管理者タブレット/PCのWebアプリ（MediaRecorder API）＋ EMEET M220等の会議用マイクで録音

② 即時アップロード
  通信環境が安定しているため、録音終了と同時にSupabase Storageへアップロード
  （オフラインバッファ機構は不要 → 実装をシンプル化）

③ 議事録生成 ＆ クエスト抽出（1API呼び出しで完結）
  音声ファイルをGemini APIへ直接入力し、プロンプトで以下を同時出力させる：
    - 決定事項・共有事項・注意点（議事録サマリー）
    - クエスト候補JSON（タスク名／想定人数／想定時間／担当候補）
  ※話者ラベルは不要なため、文字起こしと要約を分離せず一括処理でよい

④ 管理者確認
  生成結果を管理者画面にプレビュー表示 → ワンタップで補正・承認 → クエストボードへ即時公開
```

## 前回案からの簡略化ポイント
- ❌ Google Cloud Speech-to-Text（話者分離）→ 不要と判明し削除
- ❌ オフラインファースト設計（ローカル保存→後で同期）→ 通信安定のため不要
- ✅ Gemini APIへの音声直接入力で「文字起こし＋要約＋クエスト抽出」を1ステップに統合
- ✅ マイクは全員の声を拾えれば十分なため、360度会議用マイク1台で足りる（複数マイク・ミキサー不要）

## 非機能要件との関係
- 15分程度の朝会音声に対し、録音終了から議事録生成・クエスト抽出完了まで**60秒以内**（バックグラウンド処理）を目標とする。
- 通信環境が安定しているため、アップロード自体のボトルネックは小さく、目標達成の現実性は高い。

## データ項目（朝会・議事録データ）
朝会ID、実施日、音声ファイルURL、全文文字起こしテキスト、生成議事録サマリー、抽出クエスト案JSONリスト、作成者ID
