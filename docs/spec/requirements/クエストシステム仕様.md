# クエストシステム仕様

> [[浮遊街アプリ 統合ナレッジベース (Master Index)]] の子ノート（2-A）

> **クエストカテゴリの母体**: 浮遊街で想定される全業務（15ドメイン）の分類と、実行形態（現地／遠隔／ハイブリッド）・担当AIエージェントの3軸モデルは [[業務カテゴリ体系とAIエージェント設計]] に定義。クエストマスタの `category_id` / `execution_mode` / `required_certification` はこの体系に準拠する。

## スキルと職業（ジョブ）
- **スキルレベル**: Lv.1（見習い）〜Lv.5（師匠）の5段階。
- レベルに応じてタスクの想定工数（生産性）が変動する（熟練度連動の報酬動的算出はPhase 2）。
- **職業（ジョブ）の自動付与**: 複数スキルの掛け合わせによって自動判定される。
  - 例：農業Lv3 ＋ 料理Lv2 ＝『里のシェフ』
- **転職クエスト**: スキル数値のみでなく、メンバーからの「推薦」やイベント企画等のコミュニティ体験（信頼・実績）を上位職への昇格要件とする。単なる数値ゲームにしない設計思想。

## クエストボードとライフサイクル（v13準拠の運用フロー）
1. **クエストボードの一元集約**: 手動登録および朝会議事録から自動抽出されたクエストを統合表示。
2. **受注申請**: ユーザーが参加申請を行うとステータスは「申請中」。
3. **運営による審査・指示出し**: 「いつ・どこで・何を任せるか」を指示し、承認（マッチング成立）。
4. **完了報告**: Before/After写真（必須）＋実施時間を添付して提出。
5. **日次承認サイクル（1日おき）**: 運営が報告を確認し「承認」または「差戻し」。
6. **承認完了＆Uii支払い案内**: 確定Uii額とEumo送付用リンクを発行。
7. マイページへの獲得XP・貢献バッジ表示（モチベーション設計）。

## 朝会録音・議事録自動生成 ＆ クエスト自動起案（Phase 1前倒し機能・最優先）
対面朝会（話者分離不要・通信環境安定という前提）を踏まえた具体的なマイク選定・パイプライン設計は [[朝会議事録自動生成システム仕様]] に分離して詳細化した。概要は以下の通り。

| ステップ | 内容 |
| --- | --- |
| ①朝会音声録音 | 管理者タブレット/PC＋会議用マイク（EMEET M220等）からワンタップで録音 |
| ②即時アップロード | 通信環境が安定しているため録音終了と同時にSupabase Storageへ自動送信 |
| ③議事録生成＆クエスト候補抽出 | Gemini APIへ音声を直接入力し、議事録サマリーとクエスト候補JSONを1ステップで同時生成 |
| ④ワンタップ起案 | 運営が報酬Uii・難易度・時間を確認・補正し、承認してクエストボードへ即時公開 |

- 非機能要件：15分程度の朝会音声に対し、録音終了から議事録生成・クエスト抽出完了まで**60秒以内**（バックグラウンド処理）。

## クエスト完了報告・キャンセル
- 会員キャンセル：クエスト開始前まで任意でキャンセル可能。未承認のキャンセルはUii/XP付与なし。
- 管理者キャンセル：天候・災害・運営都合による中止可能。理由・日時・実施者をログ保管。

## クエストカテゴリと実行形態
クエストの業務分類は [[業務カテゴリ体系とAIエージェント設計]] で定義する15業務ドメインに準拠する（施設・環境管理、建物管理、宿泊運営、飲食・カフェ、農業・食循環、イベント、教育・コミュニティ、広報、デザイン、営業・法人、EC、財務、人事、法務・リスク、世界観・ストーリー）。

- **実行形態（`execution_mode`）**: onsite（現地必須）／ remote（遠隔可能）／ hybrid。「遠隔クエスト」は独立カテゴリではなく本フラグによるフィルタ抽出として扱い、同一業務の二重登録を防ぐ。
- **資格要件（`required_certification`）**: ユンボ・重機、チェーンソー（間伐）、食品衛生等、資格・講習修了が必要な業務は `Member.certifications` と照合し、未保有者は受注できないバリデーションを設ける。スキルLv要件とは独立した安全ゲートとして機能させる。

## データ項目（クエスト関連）
クエストID、タイトル、概要、業務カテゴリID、実行形態（onsite/remote/hybrid）、必要資格、標準Uii報酬、実行指定日時、指定場所、申請ステータス（申請中/指示済み/報告済み/承認完了/差戻し）、Before/After写真URL、実施時間、承認担当者ID、確定支払Uii額、Eumo送付用URL、起案元区分（朝会自動抽出／手動起案）

## Phase区分
- **Phase 1**: クエストボード集約、手動＋朝会自動抽出、目視承認・差戻し運用
- **Phase 2**: スキルツリーの可視化、熟練度連動の報酬動的算出、上級職・称号付与、推薦機能
- **Phase 3**: 完全自動化された承認フロー検討、他コミュニティへのクエスト定義の横展開
